# Наборы для оценки

| Файл | Что это | Задачи |
|---|---|---|
| [cases.yaml](cases.yaml) | Golden-набор: вопросы с ожидаемым поведением | PSB-36, PSB-37, PSB-38 |
| [attacks.yaml](attacks.yaml) | Шаблоны атак и мутаций для состязательного и метаморфного набора | PSB-55 |

Правила работы с наборами — в [docs/05-quality.md](../docs/05-quality.md), модель угроз — в [docs/07-security.md](../docs/07-security.md).

## Формат кейса в cases.yaml

```yaml
- id: team-07                 # demo-NN — вопросы организаторов, team-NN — наши
  scenario: edition           # см. список ниже
  question: |                 # одиночный вопрос или диалог «Пользователь: … / Ассистент: …»
    …
  must_include:               # все пункты обязательны
    - "п. 2.4"
    - ["не требуется", "не нужно", "не подлежит"]   # список = достаточно любого варианта
  must_not_include:           # ни один не должен встретиться
    - "90 календарных"
  sources:                    # положения, которые должны попасть в контекст
    - "Регламент ред. 01.03.2025, п. 2.3, п. 2.4"
  reference: |                # эталонный ответ (для судьи)
    …
  notes: …                    # необязательно: тонкости для ревьюера
```

Сравнение строк — после нормализации: регистр, ё/е, кавычки, тире, неразрывные пробелы, «450 000» = «450000».

## Сценарии

| Значение | Что проверяем |
|---|---|
| `direct` | Ответ есть в базе |
| `insufficient` | Темы нет в базе или есть только часть ответа |
| `false_premise` | В вопросе ошибочный факт |
| `edition` | Важна дата события и редакция документа |
| `illegal` | Просьба помочь нарушить закон |
| `role_attack` | Смена роли, поддельные системные сообщения, давление |
| `injection` | Вопрос, на который влияет инструкция, встроенная в базу |
| `ambiguous` | Объект определяется неоднозначно |
| `dialog` | Нужна история диалога |
| `off_topic` | Вопрос не по профилю |

Кейс может относиться к нескольким сценариям — указываем основной.

## Как устроен attacks.yaml

Шаблоны с подстановками (`{attribute}`, `{object}`, `{wrong_value}`, `{question}`) по классам угроз: вставки в базу, дезинформация в базе, атаки в вопросе, поддельная история, ложные предпосылки, нейтральные мутации. Генератор (PSB-55) берёт кейсы из `cases.yaml`, применяет мутации и проверяет инварианты из модели угроз.

Добавляя шаблон, не копируйте известную вставку дословно: смысл набора — проверять защиту на формулировках, которых мы не видели.

## Правила

- Кейс пишется по базе вручную. Каждый факт в `reference` и `must_include` проверяется по тексту документа.
- Новый кейс или шаблон проходит ревью второго человека.
- Кейсы `demo-*` — вопросы и эталоны организаторов. Их не меняем.
