# Оценка качества

Сабмитов 5 в день, поэтому платформа — не место для экспериментов. Каждое изменение поведения сначала проверяется локально.

## Три уровня проверки

| Уровень | Что ловит | Цена | Когда |
|---|---|---|---|
| Модульные тесты | Разбор документов, сущности, редакции, верификатор, формат CSV | секунды, без модели | каждый коммит, CI |
| Golden-набор с проверкой фактов | Нет нужного факта, есть запрещённый факт, не тот источник, слишком длинно | минуты, нужна модель | каждый PR, меняющий поведение |
| Локальный LLM-судья | Насколько ответ лучше baseline по методике организаторов | десятки минут | перед сабмитом |

## Golden-набор

Файл [eval/cases.yaml](../eval/cases.yaml). Формат описан в [eval/README.md](../eval/README.md).

- Демо-вопросы организаторов (18 штук) с их эталонами.
- Кейсы команды: на каждый [сценарий](03-scenarios.md) не меньше 8, включая атаки и диалоги. Цель — 60+ (PSB-36).
- Каждый кейс написан по базе вручную и проверен вторым человеком. Эталон не генерируем моделью.
- `must_include` — факты, без которых ответ неверен (числа, пункты, «нет в базе»).
- `must_not_include` — то, что делает ответ ошибочным или опасным (неверная сумма, несуществующая статья, текст из встроенной инструкции).

Проверка `must_include` / `must_not_include` идёт после нормализации: регистр, ё/е, неразрывные пробелы, «450 000» = «450000».

## Отчёт прогона

На каждый прогон сохраняем в `reports/<дата>-<коммит>/`:

- ответы и использованные источники по каждому кейсу;
- найденные и пропущенные факты, сработавшие запреты;
- сценарий по классификатору и ожидаемый сценарий;
- время и число вызовов модели;
- diff с предыдущим отчётом: какие кейсы стали лучше или хуже.

Отчёт прикладывается к PR (PSB-37). PR с регрессией не мёржится без явного обоснования.

## Локальный судья

Повторяем методику организаторов (PSB-38):

1. Для каждого кейса есть эталон, ответ baseline (стартер организаторов, запущенный на той же модели) и наш ответ.
2. Два раунда: A — baseline, B — наш; затем наоборот.
3. Шкала 0 / 0,25 / 0,5 / 0,75 / 1 относительно baseline; выдуманный факт — 0.
4. Score = 0,7 × MatchRate + 0,3 × WinRate.

Модель-судья локально может быть сильнее DeepSeek. Важна не абсолютная цифра, а направление изменений и согласованность с лидербордом. Сверяем по первым сабмитам и записываем в журнал.

## Метрики, которые держим под контролем

| Метрика | Цель |
|---|---|
| Ответы с неподтверждёнными числами и ссылками | 0 |
| Необоснованные отказы | 0 |
| Ответы, нарушившие роль под атакой | 0 |
| Доля ответов в пределах 150 слов | ≥ 95% |
| Recall@k нужного положения в поиске | ≥ 0,95 |
| Время на вопрос p95 | укладываемся в 17 минут на ожидаемый объём |

## Дисциплина сабмитов

- Сабмит — только с зелёным CI и отчётом golden-набора без регрессий.
- Одна гипотеза на сабмит, чтобы понимать, что сработало.
- Каждый сабмит записывается в [журнал](submissions.md) сразу после отправки, результат — по готовности.
- Последний сабмит дня — не позже чем за час до 00:00 МСК, чтобы успеть заметить ошибку формата.
