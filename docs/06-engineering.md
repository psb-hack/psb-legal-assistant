# Инженерные стандарты

Решение оценивают эксперты, которые будут читать код. Код должен читаться как аккуратная инженерная работа, а не как сгенерированный набор функций.

## Код

**Язык и инструменты.** Python 3.10+, `ruff` (lint и format), `mypy --strict` или `pyright` для ядра, `pytest`. Конфигурация — в `pyproject.toml`.

**Структура.**
- Один модуль — одна ответственность. Модули ядра не знают о веб-сервисе и CSV.
- Зависимости направлены внутрь: `solution.py` и HTTP API зависят от ядра, ядро не зависит от них.
- Внешние вызовы (прокси, файловая система, время) — за тонкими интерфейсами, чтобы ядро тестировалось без сети.
- Никаких модулей с именами `utils.py`, `helpers.py`, `common.py`, `misc.py`. Если функцию некуда положить — не хватает понятия в модели.

**Имена.** Предметные: `Provision`, `ContractNumber`, `effective_edition(date)`, `unsupported_claims`. Не `data`, `result`, `process()`, `handle()`, `manager`.

**Функции.** Короткие, один уровень абстракции. Нет флагов, переключающих поведение (`do_thing(x, mode=2)`) — вместо них две функции. Нет изменяемых аргументов по умолчанию.

**Данные.** Неизменяемые `@dataclass(frozen=True)` для доменных объектов, `Enum` для конечных наборов (тип документа, сценарий). Никаких словарей с «магическими» ключами между модулями.

**Константы.** Пороги, лимиты, шаблоны ответов — именованные константы рядом с местом использования или в настройках. Число без имени допустимо, только если оно очевидно (0, 1).

**Ошибки.** Ловим конкретные исключения там, где можем что-то сделать. `except Exception` — только на границе (обработка одного вопроса, HTTP-обработчик), с логом типа ошибки и без секретов. Молча проглатывать ошибки нельзя.

**Логи.** В stderr, коротко: что произошло, с каким вопросом (id), сколько заняло. Без ключей, без полного текста документов, без персональных данных.

**Комментарии.** Объясняют «почему», а не «что». Комментарий, пересказывающий следующую строку, удаляется. Докстринги — на публичных функциях модуля, если имени и типов недостаточно.

**Промпты.** Хранятся как константы в отдельном модуле, с версией в имени или комментарии. Изменение промпта — это изменение поведения: нужен отчёт golden-набора.

## Тесты

- Каждый детерминированный компонент покрыт модульными тестами: разбор документов, сущности, редакции, верификатор, запись CSV.
- Модель в тестах заменяется фейковым транспортом. Тесты не ходят в сеть.
- Тест называется по поведению: `test_alfa_trade_does_not_match_alfa_trading`, а не `test_entities_2`.
- Баг, найденный в golden-наборе или на лидерборде, сначала превращается в тест.

## Без «нейрослопа»

Решение не должно выглядеть как типичный сгенерированный проект. Конкретно:

**В коде:** нет мёртвого кода и закомментированных блоков; нет «на всякий случай» параметров, которые никто не передаёт; нет одинаковых try/except в каждой функции; нет классов-обёрток над одной функцией; нет декоративных эмодзи и баннеров в логах.

**В текстах (README, docs, PR):** конкретика вместо общих слов. Не «мощное масштабируемое решение на базе передовых технологий», а «гибридный поиск BM25 + bge-m3, recall@8 = 0,97 на 64 кейсах». Если утверждение нельзя проверить — его не пишем.

**В интерфейсе:** рабочий инструмент юриста. Плотная читаемая типографика, акцент на тексте ответа и источниках. Нет фиолетовых градиентов, «искр» и эмодзи, приветственных экранов на полстраницы и анимаций ради анимаций. Каждый элемент нужен для работы.

**В ответах ассистента:** см. антипаттерны в [сценариях](03-scenarios.md#антипаттерны).

## Definition of Done

Задача в Jira закрывается, когда:

1. Код в main через PR, CI зелёный, есть одно ревью.
2. Критерии готовности из задачи выполнены и проверены ревьюером.
3. Новое поведение покрыто тестами или кейсами golden-набора.
4. Документация обновлена, если изменилось поведение, архитектура или запуск.
5. Для изменений поведения ассистента — отчёт golden-набора приложен к PR.

## Ревью

Ревьюер проверяет не только «работает ли», но и: понятно ли без автора, нет ли скрытой связи с конкретной демо-базой (захардкоженные номера договоров в логике — нельзя, только в тестах), не появилось ли возможности выдумать факт.
