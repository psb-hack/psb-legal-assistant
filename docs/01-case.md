# Кейс и правила оценки

Выжимка из кейса ПСБ и Технического регламента. Первоисточники — в [папке организаторов](https://drive.google.com/drive/folders/1lendasLVlcKUcuM8mOrWKHD-C2dWtm9F). При расхождении прав первоисточник; найдёте расхождение — поправьте этот файл.

## Что строим

Ассистента для юристов банка. Он отвечает на вопросы только по предоставленной базе нормативных документов, ссылается на конкретные положения и прямо говорит, когда данных недостаточно. Придумывать нормы, документы и факты нельзя. Отказывать, когда ответ в базе есть, тоже нельзя.

## Два этапа сдачи

| Этап | Что сдаём | Кто оценивает |
|---|---|---|
| Во время хакатона | ZIP с `solution.py` на платформу | LLM-судья, лидерборд |
| В конце хакатона | Репозиторий (или ZIP) + PDF-презентация | Эксперты, затем защита в финале |

## Автоматический сабмит

**Вход.** Платформа кладёт в `DATA_DIR` (по умолчанию `data`) файлы `questions.csv` (`id,question`, UTF-8) и `knowledge-base.zip`. Каждая строка — независимый кейс: одиночный вопрос или короткий диалог в формате `Пользователь: …` / `Ассистент: …`. Отвечаем на последнюю реплику пользователя. Состояние между кейсами не переносится.

**Выход.** `submission.csv` в рабочем каталоге: ровно две колонки `id,answer`, UTF-8, стандартное CSV-экранирование, каждый `id` из входа ровно один раз, ответ непустой и не длиннее 10 000 символов. Рекомендуемая длина — до 150 слов.

**Архив.** Файлы в корне без внешней папки: `solution.py`, `requirements.txt`, дополнительные корневые `.py`-модули, при желании готовый индекс. Вложенные папки с модулями на платформу не переносятся. Базу и вопросы в архив не кладём.

**Зависимости.** Только пакеты и версии из `requirements.txt` организаторов (fastapi, httpx, openai, numpy, faiss-cpu, chromadb, rank-bm25, bm25s, scikit-learn, rapidfuzz, pandas, pypdf, python-docx, langchain и др.). `pip install` из кода запрещён. sentence-transformers и torch в списке нет, поэтому эмбеддинги и реранкер — только через прокси.

**Лимиты.** 5 сабмитов в день (сброс в 00:00 МСК), архив до 128 МБ, 8 CPU и 16 ГБ RAM, 20 минут на весь прогон.

**Модели.** Один локальный OpenAI-совместимый прокси для всего:

| Назначение | Модель | Эндпоинт |
|---|---|---|
| Генерация | DeepSeek V4.1 Flash | `POST {LLM_BASE_URL}/chat/completions` |
| Эмбеддинги | BAAI/bge-m3 | `POST {LLM_BASE_URL}/embeddings` |
| Реранкер (необязательно) | Qwen3 Reranker 8B | `POST {LLM_BASE_URL}/rerank` |

Заголовок `Authorization: Bearer {LLM_API_KEY}`. Имена моделей берём из окружения, а не из кода.

**Переменные окружения.** `LLM_BASE_URL` / `OPENAI_BASE_URL`, `LLM_API_KEY` / `OPENAI_API_KEY`, `LLM_MODEL` / `OPENAI_MODEL` / `GEN_MODEL`, `DATA_DIR`, `TEMPERATURE`, `MAX_TOKENS`, `MAX_WORKERS`, `TOP_K`, `CHUNKER`, `EMB_MODEL`, `RERANKER_MODEL`, `RERANKER_TOP_N`.

## Как считает LLM-судья

Для каждого вопроса судья сравнивает наш ответ с ответом baseline, ориентируясь на эталон (golden). Два раунда со сменой порядка A/B, в каждом — оценка нашего ответа относительно baseline:

| Оценка | Значение |
|---|---|
| 1,00 | значительно лучше |
| 0,75 | немного лучше |
| 0,50 | сопоставимо |
| 0,25 | немного хуже |
| 0,00 | значительно хуже |

Балл за вопрос — среднее двух раундов. **Выдуманный факт обнуляет вопрос целиком.**

- MatchRate — средний балл по всем оценённым вопросам.
- WinRate = W / (W + L), где победа — балл больше 0,5, поражение — меньше 0,5, ничьи не учитываются.
- **Score = 0,7 × MatchRate + 0,3 × WinRate.**

Публичный лидерборд считается на public-подмножестве, итог — на private. Эталоны и ответы baseline не раскрываются.

### Что из этого следует

1. Ничья с baseline почти ничего не даёт. Нужно стабильно быть «немного лучше»: точнее ссылки, честнее границы, короче и по делу.
2. Одна выдумка стоит дороже, чем десяток неидеальных формулировок. Проверка ответа перед отправкой обязательна.
3. Стиль эталонов в демо-наборе одинаковый: прямой ответ, документ и пункт, затем чего не хватает. Длина обычно 30–80 слов.

К экспертам допускаются только команды с ненулевым баллом судьи, **работающим веб-чатом** и полным комплектом материалов.

## Обязательные ограничения

- Ответы только по базе. Внешние источники и знания модели для юридических утверждений не используются.
- Каждый юридически значимый вывод подтверждается ссылкой на существующий документ и положение.
- На непрофильные вопросы ассистент вежливо обозначает границы компетенции.
- Ключевая логика поиска, ответа, проверки и отказа — наша и доступна для проверки.
- Решение должно работать на DeepSeek V4.1 Flash и не зависеть от возможностей других моделей.
- Никаких ключей и реальных персональных данных в репозитории.
