# Как работаем

## Доска

Jira, проект **PSB**: [доска](https://d12-team.atlassian.net/jira/software/projects/PSB/boards/100). Доступ — через приглашение в рабочее пространство d12-team. Нет доступа — напишите тимлиду.

- **Без спринтов и дат.** Задачи стоят в колонке To Do в порядке выполнения, сверху вниз. Тот же порядок с разбивкой по фазам — в [README](../README.md#порядок-задач).
- **Эпики A–H** — направления работы.
- **Метки p0 / p1 / p2.** p0 — без этого нет сильного сабмита или допуска к экспертам. p1 — заметно поднимает балл. p2 — полировка.
- **Колонки:** To Do → In Progress → In Review → Done. В Done задача уходит только по [Definition of Done](06-engineering.md#definition-of-done).
- **Порядок меняем осознанно.** Узнали что-то новое (например, после сабмита) — перетащите задачу на доске и поправьте таблицу в README в том же PR.

## Как взять задачу

1. Возьмите верхнюю свободную задачу в To Do. Если она зависит от незавершённой задачи выше, возьмите следующую.
2. Назначьте себя и переведите задачу в In Progress.
3. Прочитайте задачу целиком, включая «Материалы». Если непонятен критерий готовности, уточните в комментарии к задаче до начала работы.
4. Одновременно в работе у человека — не больше двух задач.

## Ветки и коммиты

- Ветка от `main`: `psb-<номер>-<коротко>`, например `psb-31-claim-verifier`.
- Коммиты в стиле Conventional Commits с ключом задачи: `feat(PSB-31): check point references against context`. Типы: `feat`, `fix`, `refactor`, `test`, `docs`, `chore`, `eval`.
- Один PR — одна задача. Большую задачу делим на подзадачи в Jira.

## Pull request

- Заполните [шаблон](../.github/pull_request_template.md): задача, что изменилось, как проверено, риски.
- Откройте PR — задача переходит в In Review, пока идёт CI.
- Ревью не требуется: автор сам вливает PR, когда CI зелёный. Второе мнение — по желанию.
- PR открывается в main, а не в ветку другого PR: иначе изменения остаются в промежуточной ветке и до main не доходят.
- Мёрж — squash, сообщение по правилам выше.
- После мёржа задача переводится в Done, если выполнены все критерии.

## Сабмиты

Отправляет один ответственный за день, по [правилам](05-quality.md#дисциплина-сабмитов). Результат — в [журнал](submissions.md) и в общий чат.

## Синхронизация

Короткий созвон раз в день: что сделано, что дальше, что блокирует. Решения, которые меняют архитектуру или поведение, фиксируем в ADR или в docs, а не в чате.
